# 0015 — Scalar SSE: Rust's `f32`/`f64` with the x86 rules coded by hand

- **Status:** Accepted (2026-10-12). Superseded by 0024 for MXCSR and for computation in the interpreter (2026-10-13).
- **Date:** 2026-10-12

## Context
coreutils' `sort` and `tail` use scalar SSE2 instructions (`movsd`, `comisd`, `cvtsi2sd`, `addsd`, …). The basic IEEE operations are identical on x86 and AArch64, but some rules are not: NaN propagation, the NaN generated by invalid operations, `min`/`max`, out-of-range conversions to integer. In addition, MXCSR can change rounding and exceptions.

## Decision
- Arithmetic with Rust's `f32`/`f64`: correct rounding to nearest, ties to even.
- x86 rules that differ from IEEE/AArch64 implemented explicitly on the bits, in `crates/armor-cpu/src/float.rs` (details and verification in `tech/floating-point.md`).
- **Only the default MXCSR control** (exceptions masked, round to nearest, no FZ/DAZ). Any other value stops armor with "not supported yet": no silent wrong results.
- The MXCSR exception flags are not updated.

## Alternatives considered
- **Softfloat for everything:** exact in every rounding mode and with the flags, but slower, and it needs a crate or a lot of code. To be reconsidered together with the x87 (M4), which requires it anyway for the 80 bits.
- **Setting AArch64's FPCR according to MXCSR:** would give rounding and FZ in hardware, but it requires `unsafe`/assembly in `armor-cpu` (today `forbid(unsafe_code)`) and does not solve NaNs and conversions.

## Consequences
- \+ Simple, fast, covered by `difftest` and unit tests.
- − Programs that change the rounding mode (rare: some numerical libraries, `fesetround`) stop with a clear message.
- − Programs that read the exception flags (`fetestexcept`) see wrong values ⚠️: there is no measured case yet.
