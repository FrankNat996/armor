# 0029 — 32-bit x86 guests (i386)

- **Status:** Accepted (2026-10-13)
- **Date:** 2026-10-13
- Wider context: the Steam and Proton goal (`tech/steam.md`, milestone M9).

## Context
Steam's Linux client is an i386 PIE (`ubuntu12_32/steam`), and the bootstrap brings 39 32-bit ELFs out of 54 (`tech/steam.md`, measured inventory). Proton also runs 32-bit Windows programs. armor today runs only x86-64.

Facts measured on 2026-10-13:
- under armor all the host mappings (binary, libraries, heap, the 32 GiB permission table) are above 4 GiB; below there is only the guest;
- oracles: `qemu-i386` (qemu-user 10.0.13) and the Xeon X5675 (the kernel's IA-32 emulation) give the same output on a static i386 hello with `sin` and `atan2`;
- toolchain: `gcc-i686-linux-gnu` 14.2.0 and `libc6-dev-i386-cross` (glibc 2.41) installed;
- the i386 libm uses the x87 transcendentals (ADR-0030).

## Decision
- **A single armor for both:** the mode (64 or 32 bits) is chosen from the loaded ELF (`ELFCLASS32`, `EM_386`); `execve` relaunches armor as today.
- **Memory: identity below 4 GiB.** As for x86-64, guest address = host address; the mappings of a 32-bit guest are all below 4 GiB (an allocator that looks for free space there, `MAP_FIXED_NOREPLACE`). Interpreter, permission table and JIT stay the same; computed addresses are truncated to 32 bits.
- **Decoder:** 32-bit mode in the same decoder (32-bit operands and addresses by default, no REX: 40–4F are `inc`/`dec`; `push`/`pop` of the segment registers, `pusha`/`popa`, BCD, `bound`, `les`/`lds`, … come back) and in the length-only decoder.
- **Syscalls:** the i386 ABI (`int 0x80`, 32-bit numbers and structures, `socketcall`, `ipc`, `mmap2`, `set_thread_area` for the TLS on `%gs`) translated onto the same implementations as x86-64, converting the structures. No vDSO at first: without `AT_SYSINFO` glibc uses `int 0x80`.
- **Engines:** first the interpreter, complete and verified against `qemu-i386` and the Xeon; then the JIT for 32 bits, with lockstep.
- **Tests:** i386 test programs (asm and C, static and dynamic) in `difftest` against `qemu-i386`, and with `--oracle` against the Xeon.

## Implementation
- **2026-10-13, increment 1a:** decoder and length-only decoder in 32-bit mode (`Mode::Compat32`); 4,622,370 i386 instructions with objdump's length.
- **2026-10-14, increment 1b:** execution of static i386 programs in the interpreter.
  - **Memory:** `AddressSpace::set_ceiling` (`I386_CEILING` = `0xffff_e000`): the mappings whose address armor chooses (`map_anywhere`, `MAP_SHARED` without an address, the stack, `ld.so`) are searched from the top down below the ceiling, first in armor's tables then with `MAP_FIXED_NOREPLACE`. i386 PIE at `0x400000` (`I386_PIE_BASE`).
  - **CPU:** `Cpu::mode`; 32-bit stack, jumps and `rip`; linear address truncated to 32 bits *after* the segment base (i386 glibc reads the TLS with negative offsets from `gs`); string instructions, `loop` and `xlat` with `esi`/`edi`/`ecx`/`ebx`; `int 0x80` becomes `Step::Syscall`. Segments: `Cpu::segments` with the `fs`/`gs` selectors and the three TLS entries of the GDT (12–14, as in Linux x86-64); `mov gs, …` loads the entry's base, `mov …, gs` reads the selector; `ds`/`es`/`ss` accept only `0x2b`.
  - **Syscalls:** `armor_linux::syscall::i386` (62 numbers), with the x86-64 implementations where the structures coincide and conversions for 32-bit `iovec`, `rlimit`, `timespec`/`timeval`, `user_desc`, `_llseek`, `mmap2`. Result in `eax` with the upper half zero.
  - **Loader:** ELF32 (`armor-elf`), stack of 4-byte words, platform `i686`, no `AT_SYSINFO`.
  - **Engine:** always the interpreter for 32-bit code, even with `--jit` (which is still passed to x86-64 children).
  - **Tests:** `tests/guest/asm32/`, `tests/guest/c32/` and 6 sources from `tests/guest/c/` in `difftest` against `qemu-i386`, and with `--oracle` against the Xeon. Two cases in which `qemu-i386` does not serve as oracle (`testing.md`).

## Alternatives considered
- **Base with offset** (host address = base + guest in a 4 GiB reservation): isolates armor better from the guest, but every access, the JIT and the syscalls with pointers would have to be rewritten. Discarded.
- **JIT together with the interpreter:** useful performance sooner, but more work per increment and correctness harder to isolate. Chosen: the interpreter first.

## Consequences
- \+ Reuses almost everything: memory, interpreter, signals, processes, sandbox.
- − The 32-bit guest's address space is limited to what the host leaves free below 4 GiB (today all of it, measured; to be rechecked if the host changes).
- − A second syscall table to maintain, with its 32-bit structures.
