# 0017 — Signals: delivered by the host kernel, x86_64 frame built by armor

- **Status:** Accepted (2026-10-12)
- **Date:** 2026-10-12

## Context
Until 2026-10-12 `rt_sigaction` only recorded: the guest's handlers were never called. Many real programs install handlers (`sort` for temporary files, language runtimes for faults, shells for SIGCHLD and SIGINT). What is needed: delivery between instructions, mask, pending signals and queueing, interrupted syscalls, the x86_64 frame and `rt_sigreturn`, guest faults as signals.

## Decision
- **The host kernel acts as queue and mask.** armor installs in the host a minimal handler (it records the signal and leaves it blocked) for the signals the guest handles. It mirrors the guest's mask in the host and passes `kill`/`tgkill`/`tkill` to the host. Pending signals, real-time queueing and blocking are thus handled by the real kernel.
- **Faults are synchronous signals generated by armor** from the interpreter's errors, with the `si_code` and address Linux would use.
- **Delivery in the main loop**: after every syscall, every 10,000 instructions, and before running a syscall if a signal is already pending.
- **Frame identical to Linux x86_64's**, with the FPU state in FXSAVE format (no XSAVE in the CPU model).
- **Interrupted syscalls:** host handlers without `SA_RESTART`; armor restarts or returns `EINTR` according to the guest's `SA_RESTART` and a list of restartable syscalls.

Details and verification in `tech/signals.md`.

## Alternatives considered
- **Queue and mask entirely in armor** (the host handler does not block, armor keeps its own queue): more code, and real-time queueing, `sigpending` and the interaction with blocking syscalls, which the kernel already does, would have to be redone by hand.
- **Delivery only at syscalls:** simpler, but a computation loop without syscalls would never receive a timer or a Ctrl-C.

## Consequences
- \+ Kernel semantics for pending signals and mask; the `c/signals` test is identical to qemu at the first attempt.
- \+ The signal check costs one atomic load every 10,000 instructions.
- − A narrow window between the check before a syscall and entry into the host syscall: a signal that arrives there does not interrupt a blocking syscall (`tech/signals.md`).
- − Signals reserved for the host (SIGSEGV & co.) sent by another process do not reach the guest.
- − With threads (M3) a per-thread mask and delivery to the right thread will be needed.
