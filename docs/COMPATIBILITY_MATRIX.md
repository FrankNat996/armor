# Compatibility matrix

Required by the guiding document (§7). **Source:** reproducible results only. An entry goes in here when there is a command that verifies it (usually `cargo xtask difftest`). Last update: 2026-10-14 (i386 programs, ADR-0029; other engines, ADR-0032; FEX on 4K pages; the first x86 game, Doki Doki Literature Club; Windows programs with `armor install`, ADR-0033; Spotify, the first `.deb` installed with `armor install`; XnView MP, KeePassXC (AppImage) and Sublime Text (`.tar.xz` archive), installed with `armor install` and opened from the menu). Applications tested by hand, outside `difftest`, say so in their row and stay at level 1 until they have a reproducible case. Generating the matrix from the measurements is an item of M10 (`roadmap.md`).

## Levels
| Level | Meaning |
|---|---|
| **0 — refused** | armor does not load it (see `armor inspect`) |
| **1 — starts** | it starts, but the behaviour has not been compared |
| **2 — partial** | some functions give the same result as the oracle, others do not |
| **3 — identical on the tested workload** | stdout and exit status identical to `qemu-x86_64` on every listed case |
| **4 — stable** | level 3, plus long or repeated runs without errors (no entries yet) |

"Identical on the tested workload" does not mean "compatible" in general: it holds only for the listed cases.

## Environment of all entries
- **Host:** Raspberry Pi 5, Debian 13, kernel 6.18 with 16K pages (`environment.md`); since 2026-10-14 the 4K kernel (`rpi-v8`, 39 address bits), on which armor's chain is green again (397/397 with both engines and in lockstep, oracle 216/216). The entries added after that date (Doki Doki Literature Club, the C tests for it, the FEX measurements, 7-Zip, the Windows programs, Spotify) have been tested only with 4K pages.
- **armor:** cargo profile `difftest` (optimised, with overflow checks); each case runs twice, interpreted and with `--jit` (since 2026-10-12), and must match qemu in both; `difftest --lockstep` also runs them with every translated instruction checked against the interpreter.
- **Oracle:** `qemu-x86_64` 10.0.13 with `-cpu qemu64,-svm,+ssse3,+sse4.1,+sse4.2,+popcnt` (ADR-0010; until 2026-10-13 `qemu64,-sse3,-svm`) and `-L <root>`; armor with the same root (`ARMOR_ROOT`, ADR-0013). The root is `/usr/x86_64-linux-gnu` for the test programs and busybox, `target/guest/rootfs` for coreutils, the tools of `tools.txt`, perl and python. For i386 programs (since 2026-10-14) the oracle is `qemu-i386` 10.0.13 with `-cpu qemu32,+sse3,+ssse3,+sse4.1,+sse4.2,+popcnt`, plus the Xeon X5675 (`difftest --oracle`), which decides where qemu-i386 is wrong (`testing.md`).

## Other engines (ADR-0032)
The matrix above concerns armor. The other engines (box64, FEX) and Valve's ARM64 Steam client are measured on the same cases with `cargo xtask difftest --engine box64|fex`; results, versions and method in `tech/engines.md`. No compatibility level is assigned to an engine without that measurement.
- **Pi 5, 16K pages (2026-10-14):** box64 v0.4.4 identical to qemu in 218 cases out of 397 (143/153 real x86-64 programs, 11/109 i386 cases), armor in 397 out of 397; FEX-2610 does not start (jemalloc rejects 16K pages); Valve's ARM64 client terminates with SIGSEGV (linked for 4K pages).
- **Pi 5, 4K pages (2026-10-14):** FEX-2610 identical to qemu in 345 cases out of 397: all 203 real programs (x86-64 and i386), 90 of the 126 C test programs, 52 of the 68 assembly ones; the differences are in the exactness tests (x87, signals, MXCSR and NaN, faults). armor 397 out of 397. Valve's ARM64 client starts, signs in and installs Valve's FEX layer and Proton by itself.
- **Windows programs:** above, "Windows programs".
- Missing: x86-64 box64 on 4K pages, FEX's speed (M10), other ARM64 CPUs (M9).

## How to add an entry
1. The case must be reproducible: a program in `tests/guest/`, a line in `busybox.txt`, `coreutils.txt`, `tools.txt` or `interpreters.txt`, or a new mechanism documented in `testing.md`.
2. Report version, build, level reached, functions actually tested and problems seen (with armor's message).
3. Do not promote to a higher level without the corresponding proof.
